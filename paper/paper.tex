% --- Abstract ---
\begin{abstract}
	A DNA sequence and it's reverse-complement(RC) represent the same molecule, and a model that cannot recognize this RC-symmetry wastes capacity relearning the same biological signal on both sequences. Yet, the two strands are not always functionally interchangeable: There are certain asymmetries introduced by transcription that a model can only exploit if it is shown in a consistent orientation with respect to the template and coding strands, rather than an arbitrary one. We test canonicalization, fixing which physical strand (coding or template) occupies each input position, derived from genome annotation (GFF) files, as a way to let a symmetry-aware but not fully RC-invariant/equivariant architecture (ConvNova) make use of these asymmetries. We evaluate this proof of concept on 30 tasks from multiple benchmarks comparing against both a non-canonicalized baseline and a leakage-control model that receives the same strand information as an explicit input channel, since the annotation-derived orientation signal used for canonicalization can itself leak information. Canonicalization, as implemented here, fails: across the tasks selected for full-scale evaluation, it does not outperform the leakage control model, who does show a consistent improvement over the plain baseline on most tasks. That is at least compatible with the idea that transcriptional-asymmetry information can be useful to these models ; this is only suggestive, not evidence for canonicalization itself, and the effect could equally stem from other factors. We conclude that this particular canonicalization approach does not work, while whether exploiting transcriptional asymmetry through some other mechanism could work remains an open, untested hypothesis.
\end{abstract}

\section{Introduction}\label{introduction}

One of the central goals of computational genomics is to predict
biological function directly from DNA sequences. This goal encompasses
tasks ranging from identifying functional elements, such as
promoters, enhancers, transcription factor binding sites, and splice
sites; to chromatin accessibility, gene expression, or estimating the
functional effect of genetic variants.

To address this diversity of problems, DNA foundational models (FMs)
have been developed in recent years. These models are pretrained using
self-supervised objectives on large collections of genomes to learn
generalizable features, which can then be adapted to different tasks
through fine-tuning.

Transformer-based and SSM-inspired architectures have become the dominant approach in DNA modeling and FMs. Recently, the use of CNNs, which were the dominant approach before transformers, has also been re-explored in ConvNova \citep{boRevisitingConvolutionArchitecture2025}. See section \ref{sec:related_work_transformers_and_ssm} for more details.

One of the main challenges of FMs is that DNA consists of two strands, each is the reverse complement (RC) of the other. Because a double-stranded sequence and its reverse complement describe the same physical molecule, a model that can't recognize this equivalence is wasting capacity relearning it separately for both orientations. We refer to this equivalence, that $S$, a DNA sequence and $RC(S)$, the RC of a DNA sequence, encode the same physical molecule, as DNA's RC-symmetry.

One of the main challenges of DNA modeling is designing the model architecture to exploit this RC-symmetry. It has been shown that making the model treat the RC on its input in an invariant or equivariant way improves performance as seen in \citet{zhouBetterUnderstandingReverseComplement2021} or Caduceus \citep{schiffCaduceusBiDirectionalEquivariant2024}, and it has been a leading practice for FMs since. See section \ref{sec:related_work_zhou} for more details.

But, even though \(RC(S)\) is a deterministic and reversible transformation of
\(S\) (knowing \(S\) implies knowing \(RC(S)\)), this does not
imply that these strands are functionally equivalent. \citet{moeckelStrandAsymmetriesGenomic2023} show functional asymmetries which are caused by several biological
processes. Several of
these asymmetries are associated with transcription, of which a few examples are (reviewed from \citet{moeckelStrandAsymmetriesGenomic2023}):
\begin{itemize}
	\item A GC-skew between the template and the coding strands,
	\citep{greenTranscriptionassociatedMutationalAsymmetry2003}, which in turn favors the formation of structures such as R-loops and G-quadruplexes
	(\citet{ginnoRloopFormationDistinctive2012},
	\citet{maoDNAGquadruplexStructures2018})
	\item Repetitive elements show significant transcriptional asymmetry
	\citep{georgakopoulos-soaresAsymmetronToolkitIdentification2021}.
	\item Certain elements, such as promoters, are only functional when correctly
	oriented \citep{duttkeHumanPromotersAre2015}.
\end{itemize}

Based on the available literature, few works have been found that incorporate the asymmetries shown above (see section \ref{sec:related_worl_transcriptional_asymmetry}). Most FMs focus on either:
\begin{enumerate}[label=\alph*]
	\item Processing both DNA strands in
	a fully symmetric way, as in RCPS, conjoined models
	\citep{zhouBetterUnderstandingReverseComplement2021} and Caduceus
	\citep{schiffCaduceusBiDirectionalEquivariant2024}
	\item Not explicitly incorporating this symmetry into the model architecture and instead letting the model learn it independently, as in Nucleotide Transformer
	\citep{dalla-torreNucleotideTransformerBuilding2025}, HyenaDNA
	\citep{nguyenHyenaDNALongRangeGenomic2023} and Zhou's RC-aug models
	\citep{zhouBetterUnderstandingReverseComplement2021}
\end{enumerate}

Although models that don't incorporate this RC-symmetry into their architectures could
theoretically learn it, and even be capable of accounting for the
asymmetries observed in \citet{moeckelStrandAsymmetriesGenomic2023}, better results can be observed when the RC-symmetry is incorporated explicitly into the architecture, as it can be seen in the decreased performance of \citet{zhouBetterUnderstandingReverseComplement2021} RC-aug models (see section \ref{sec:related_work_zhou}) or the general improvement of Caduceus compared to HyenaDNA \citep{schiffCaduceusBiDirectionalEquivariant2024}.

However, the best-performing model does not fit either of the previous two categories. ConvNova outperforms Caduceus, the second-best model, on several tasks despite having significantly fewer parameters\citep{boRevisitingConvolutionArchitecture2025} and despite CNNs being generally considered surpassed by transformer and SSM-inspired architectures. 

It doesn't force full RC-symmetry, but it doesn't ignore it either. Its symmetry-aware, by taking both strands as inputs, but lets the network modulate the symmetry on its own instead of forcing it through weight-tying.

This
suggests that neither ignoring symmetry nor fully forcing it is optimal, and provides grounds for exploring an intermediate direction: being symmetry-aware without forcing invariance or equivariance.

Although RC-symmetric models avoid relearning each strand separately, but it still receives the two strands in an orientation that is arbitrary with respect to transcription. In the same input position, it will sometimes receive the coding strand, and other times the template strand. As a result, it cannot exploit the transcription-linked asymmetries described above, since the model's filters would have to consistently work well with template and coding strands, implicitly forcing the model to be RC-invariant to transcriptional asymmetries.

This suggests a next step to explore: Pushing this semi-symmetrical architecture further by making the model always receive both DNA strands in a consistent orientation by making the template and coding strands always occupy predefined positions within the input.

Passing both strands in this \emph{orientation-consistent processing} would
allow the model to capture the asymmetries that occur only in that
specific strand, since if it were simply given both strands in either of
the 2 orientations, the model would be forced to learn the biological
signals that occur equally on both strands (and become RC-invariant with
respect to transcriptional asymmetries).

This orientation-consistent concept could theoretically be applied to any architecture (it just wouldn't make sense in the case of an RC-equivariant or RC-invariant architecture, as it would have no effect).

This orientation-consistent learning can be achieved through a canonicalization function. \citet{kabaEquivarianceLearnedCanonicalization2023} successfully
uses canonicalization for a wide range of domains and proposes that
the canonicalization function should be learned rather than hand-engineered.

Based on this, we present a proof of concept of this canonicalization, in which:
\begin{enumerate}
	\item For each dataset, genome annotation data is obtained to determine which parts of the sequences are transcribed and which are the template/coding strands
	\item To assess the effect of canonicalization, we train ConvNova, which is symmetry-aware without imposing RC invariance or equivariance (see section \ref{sec:methods_convnova}) on data from the Nucleotide Transformer benchmark\citep{dalla-torreNucleotideTransformerBuilding2025}, Genomic Benchmark\citep{gresovaGenomicBenchmarksCollection2023}, BEND Benchmark\citep{marinBENDBenchmarkingDNA2023}, and on chromatin profile prediction using the DeepSEA dataset\citep{zhouPredictingEffectsNoncoding2015}.
	\item Multiple versions of the canonicalization algorithm are evaluated and compared.
\end{enumerate}

The genome annotation data is obtained through GENCODE's General Feature Format (GFF) file, and since it constitutes the most reliable source available for
inferring transcriptional orientation, these results should be
interpreted as an upper bound on what is achievable for transcriptional
asymmetry through a learned function.

\section{Related work} 

\subsection{CNNs, Transformers, and SSM-inspired architectures}
\label{sec:related_work_transformers_and_ssm}

CNNs such as Basset\citep{kelleyBassetLearningRegulatory2016}, Basenji\citep{kelleySequentialRegulatoryActivity2018}, and LegNet\citep{penzarLegNetBestinclassDeep2023} were the dominant approach in DNA modeling before the rise of transformer-based architectures.

In recent years, transformer-based architectures such as
Nucleotide Transformer
\citep{dalla-torreNucleotideTransformerBuilding2025}, Enformer
\citep{avsecEffectiveGeneExpression2021}, DNABERT-2
\citep{zhouDNABERT2EfficientFoundation2024} have become the
dominant approach as FMs thanks to attention's ability to deal with long-range dependencies and focus on specific signals.

Recently, SSM-inspired architectures such as HyenaDNA
\citep{nguyenHyenaDNALongRangeGenomic2023} and Caduceus
\citep{schiffCaduceusBiDirectionalEquivariant2024} have become popular because of their ability to capture long-range dependencies without the large computational cost of transformer-based architectures.

\subsection{RC-aug, RCPS, and conjoined models}
\label{sec:related_work_zhou}
In \citet{zhouBetterUnderstandingReverseComplement2021}, 3 types of CNNs are evaluated on predicting 919 chromatin features (TF binding, histone marks, and DNase I hypersensitivity). Each model takes a single DNA sequence as input, represented as a matrix where each row is the nucleotide base and each column is the nucleotide position. The models evaluated were:
\begin{itemize}
	\item RC-augmented/RC-aug models: Data augmentation was applied by taking the RC of the sequence and keeping the target
	value, and the model was trained normally
	\item RCPS (Reverse Complement
	Parameter Sharing) models: The network's filters were designed so that
	\(f(S)=f(RC(S))\) through weight tying.
	\item Conjoined (CJ) and conjoined post-hoc models: Both $S$ and $RC(S)$ are passed separately through the same network, and their outputs are averaged. In CJ models, this averaging is applied during both training and inference, whereas in post-hoc models it is applied only at inference.
\end{itemize}

The results showed that the Conjoined post-hoc model were the best on the majority of tasks, with RCPS occasionally having a better performance than it.

\subsection{Canonicalization}
Canonicalization offers a distinct strategy for handling symmetries,
distinct from both data augmentation and architectural weight-tying.
Instead of forcing invariance within the network (as in RCPS) or
implicitly teaching it through the data (as in RC-aug), canonicalization
transforms the input to a standard orientation before it enters the
model so that the network never needs to explicitly learn or impose the
symmetry.

\citet{kabaEquivarianceLearnedCanonicalization2023} formalizes canonicalization in a generalizable way for any kind of task, by making the model \(\phi(x)\) be: \[
\phi(x)=h'(x)\cdot f\left( h^{-1}(x)\cdot x \right) 
\] Where:
\begin{itemize}
	\item \(h(x)\) is the canonicalization function: it predicts the transformation that the canonical version of \(x\) underwent, and its inverse is taken to bring \(x\) to its canonical version
	\item \(f(x)\) is the prediction function 
	\item \(h'(x)\) is the label canonicalization function: it predicts the transformation that the \(y\) of that canonical \(x\)
	underwent. On RC-invariant tasks, $h'(x)$ is the identity function for all $x$
\end{itemize}

\begin{figure}[H]
	\centering
	\includegraphics[width=0.5\textwidth]{kaba.png}
	\caption{A diagram of the canonicalization process for a task where the goal was to recognize MNIST digits' rotation in an equivariant way, where the digit is transformed to its canonical form, recognized, and then the prediction is rotated back to its original form. Figure adapted from \cite{kabaEquivarianceLearnedCanonicalization2023}}
\end{figure}

Its important to note that we use only the general concept of
canonicalization: transforming the input to a standard orientation
before processing it. It does not adopt the specific techniques that \citet{kabaEquivarianceLearnedCanonicalization2023} propose to make this function learnable end-to-end.

\section{Methods}

\subsection{Canonicalization}
\label{sec:methods_canonicalization}

The canonicalization method consists of a pre-processing pipeline that makes all the datasets orientation-consistent. It works in the following way:
\begin{enumerate}
	\def\labelenumi{\arabic{enumi}.}
	\item Extract all transcribed features, pseudogenes, and V(D)J segments (in the case of human and mouse genomes), their
	positions, and whether they are oriented in coding or template form in
	the dataset. The orientation of the features is obtained directly from
	the `Strand' field from the GFF.
	\\
	The way that features are classified as transcribed or not is: For annotations without a
	standardized type field (NCBI), the Sequence Ontology hierarchy
	\citep{eilbeckSequenceOntologyTool2005} was used to programmatically
	determine which features correspond to transcribed units; for GENCODE
	annotations, the `Feature' and `Transcript type' fields were directly used.
	\item
	Based on that, the goal is for all of those selected features (we'll call these \emph{segments} from now on) to be in their coding
	orientation by taking the reverse-complement of
	their coordinates in the genome.
	\item
	In the case where there are overlaps between segments of opposite
	orientations, applying RC to one segment is considered to
	\textbf{completely} destroy both segments (this method produced the best results, see section \ref{sec:methods_optimal_canonicalization_search} for more details). In that case, both segments are left as is.
	\item After the whole genome is canonicalized, it's then saved and the model is trained on it
\end{enumerate}

Multiple versions of this canonicalization algorithm were evaluated. For more details on the different algorithms, see section \ref{sec:methods_optimal_canonicalization_search}, and section \ref{sec:methods_evaluation_canonicalizaiton_algorithms} for the evaluation protocol.

For the downstream tasks, we need to know the sequence's position in the genome it was obtained from --- referred to as the \emph{source genome} --- to know if it's located on top of a feature selected by the canonicalization algorithm and if it should be canonicalized. Most datasets don't provide the sequence's coordinates, and in those cases, they were obtained by aligning the sequences with their respective source genome using minimap2 \citep{liMinimap2PairwiseAlignment2018}

Then, after getting the sequence coordinates, if more than 50\% of the sequence is transcribed, then the entire sequence is canonicalized along with its label. The basis of this algorithmic decision is based off the results from \ref{sec:methods_evaluation_canonicalizaiton_algorithms}

The label transformation method depends on the tasks, which are divided into 3 categories:
\begin{itemize}
	\item RC-invariant tasks where \(f(RC(S))=f(S)\), such as ChIP-seq results, for example (since it analyzes interactions on dsDNA)
	\item RC-equivariant tasks where \(f(RC(S))=T(f(S))\), with \(T\) being a known transformation over the output space. For RC-invariant tasks, $T=I$, the identity function. 
	\item Non-canonicalizable tasks where $f(S)\neq f(RC(S))$, and there isn't a known $T$ transformation. For example, in a promoter classification task, the RC of a sequence labelled as
	non-promoter might or might not correspond to a promoter. Therefore, the
	transformation of the negative class under RC cannot be determined
	solely from its original label. In these cases, canonicalization is skipped, because transforming the sequence would break its label.
\end{itemize}

For downstream tasks, regions without transcribed segments remain unmodified and passed in arbitrarily as they were on the source genome, as done in \citet{boRevisitingConvolutionArchitecture2025}. Even if the sequence falls on the negative strand and the model never saw it, the sequence won't be transformed in order to test the model's generalization.

It should also be noted that for the pretraining dataset, not all transcribed segments are
canonicalized, since when there are overlaps, the canonicalization
algorithm has to make compromises in certain places. For the downstream tasks though, it is
assumed that all transcribed segments were canonicalized, since the goal
is to evaluate how well the model learns to capture transcriptional
asymmetries, not the compromises the canonicalization algorithm had to
make.

\subsection{Network architecture}
\label{sec:methods_convnova}
ConvNova was used for the evaluation of the canonicalization's performance by training and fine-tuning it on the canonicalized dataset. The network architecture is a CNN consisting of a series of Gated Convolution Blocks (GCBs), which consist of a gated convolution \citep{yuFreeFormImageInpainting2019} with dilated filters
\citep{yuMultiScaleContextAggregation2016}, with an MLP per token or over the whole pooled sequence at the end depending on the task.

The model takes the DNA and its reverse-complement as inputs
\(\text{A}\) and \(\text{B}\) and computes the output as follows, updating the features of \(\text{A}\) depending on the gating imposed by the outputs of \(\text{B}\)
\begin{gather*}
	h=\text{GELU}(\text{convolution}(\text{A}))\\
	g=\text{sigmoid}(\text{convolution}(\text{B}))\\
	\text{A}=\text{A}+h\odot g\\
	\text{B}=\text{B}+g
\end{gather*}

\begin{figure}[h!]
	\centering
	\includegraphics[width=\textwidth]{convnova_arch.png}
	\caption{Diagram of ConvNova's architecture. Figure adapted from \cite{boRevisitingConvolutionArchitecture2025}}
\end{figure}

The dilation rate of the GCBs follows the sequence \([1,1,d,d^2,d^3,\dots]\) for
each block. After the last GCB, the masked output of \(A\) passed through and MLP, and then each token is passed through a linear layer, or the whole sequence is pooled and passed to a linear head depending on the task.

ConvNova was chosen for three reasons: it achieves state-of-the-art metrics with a relatively small number of parameters; it is neither RC-invariant nor RC-equivariant, which would nullify the effect of canonicalization; and it takes both DNA strands as input, so it could potentially better learn the asymmetries between the forward and RC strands mentioned earlier.

\subsection{Evaluation of the canonicalization algorithm}
\label{sec:methods_evaluation_canonicalizaiton_algorithms}

To evaluate the canonicalization method the training data is
pre-processed (described in \ref{sec:methods_canonicalization}) and the same pretraining and fine-tuning protocol 
in \citet{boRevisitingConvolutionArchitecture2025} paper is used (except for the minority cases where it is
explicitly stated that a different protocol was used)

For each of the tasks, as with ConvNova, the model is pretrained on hg38
using masked language modelling(MLM). 15\% of the nucleotides are masked and the model's objective
is to predict them.

For the downstream tasks, simply comparing the performance of the non-canonicalized model vs the canonicalized one isn't enough. Because the canonicalization algorithm uses additional data, it possibly introduces a data leakage that could be inflating the true improvement caused by the canonicalization algorithm.

In the gene finding task from the BEND Benchmark, for example, a task that
consists of classifying each nucleotide as exon, intron, acceptor,
donor, or nothing, the (noisy) introduction of the strand orientation data by the canonicalization algorithm produces a leakage.

To mitigate that, an ablation was designed where 3 different versions of the model are evaluated:
\begin{itemize}
	\item Baseline: The baseline model without any canonicalization
	\item Canonicalized: The model evaluated on the canonicalized datasets
	\item Leakage control: The model is evaluated on the non-canonicalized datasets with an additional input channel indicating whether that nucleotide is a positively transcribed feature (+1), a negatively transcribed feature (-1), or isn't transcribed (0)
\end{itemize}

The evaluation protocol for a model consists of 5 runs with 5 different random seeds. Those 3 versions of the model are evaluated on all downstream tasks using a fewer-parameter configuration to speed up the evaluation (see section \ref{hyperparameter-search} for the configuration details).

Then, for the tasks where a promising difference appears between the canonicalized model vs the baseline and leakage control models, that same evaluation protocol is used but with the original, larger configuration. This screening step is only used to decide which tasks deserve the additional compute of a full-scale evaluation.

The criterion for deciding if an observed difference between the canonicalized model and the other two models is promising is by computing the right-tailed p-values for the canonicalized model vs the baseline, and the canonicalized model vs the leakage control one, taking the largest of those p-values, and checking if they're low enough.

It's worth noting that for the leakage control model, because of the additional input channel, has slightly more parameters than the baseline and canonicalized models. The parameter count difference is under 0.5\% in relative terms and is therefore negligible.

\subsection{Downstream tasks}
For the choice of baselines and evaluation protocol, the original protocol established by the authors of ConvNova
\citep{boRevisitingConvolutionArchitecture2025} will be followed, unless stated
otherwise. The reason this protocol was used is that, by using ConvNova
as the architecture and only changing the data pre-processing, the
results are directly comparable.

All models were fine-tuned after being pretrained on hg38. For details
regarding how the labels of each downstream task were canonicalized, see
section \ref{sec:downstream-task-canon-classification}. The downstream tasks and their details are listed below. Each benchmark is evaluated a specific model configuration, see section \ref{sec:appendix_downstream_tasks} for more details.

\subsubsection{NT Benchmark} 
This benchmark is the one used by Nucleotide Transformer
(\cite{dalla-torreNucleotideTransformerBuilding2025}). It consists of 3
types of tasks: histone marker, splice site annotation and regulatory annotation prediction. It should be noted
that the most recent version of this benchmark was used, which wasn't the one used in the original ConvNova paper.

To evaluate the tasks, the same methodology as in HyenaDNA \citep{nguyenHyenaDNALongRangeGenomic2023} was followed, using the
Matthews Correlation Coefficient (MCC) for certain tasks and the
F1-score for others.

For canonicalization, GRCh38 was used as the source genome and the annotations were obtained from the Genome Reference Consortium, since all the datasets come from human samples. The tasks were evaluated using a pooling downstream head.

\subsubsection{Genomic Benchmark}
This is a multi-species benchmark, consisting of human, mouse,
roundworm, and fruit fly samples. Its tasks consist of species classification, enhancer and regulatory annotation prediction.

For canonicalization, the following source genomes were used: hg38 for
the human sample tasks, GRCm39 from the Genome Reference Consortium for the mouse tasks, and for the roundworm and fruit fly
tasks the NCBI reference genomes were used. The tasks were evaluated using a pooling downstream head.

Note that for \texttt{human\_ensembl\_regulatory}, the baseline model's performance dropped compared to the original ConvNova paper because the whole sequence is passed to the model instead of a trimmed version of it like in the original ConvNova paper (see more details in section \ref{sec:appendix_downstream_tasks}). It's theorized that this happens because of the pooling head diluting the signal located at the start of the sequence used for prediction. This choice was made because it isn't realistic to have the biological signal consistently located at the start of the sequence.

\subsubsection{BEND Benchmark}
The model was evaluated on two tasks. gene finding, where each nucleotide of a DNA sequence is classified as donor, acceptor, intron, exon, or neither, along with the strand it lies on, and CpG methylation, where given a DNA sequence multilabel classification is
done on whether it is methylated or not in different cell lines.

The chromatin accessibility and histone modification tasks were considered redundant when comparing them to the rest of the other benchmarks' tasks, and therefore were excluded from the evaluation

The zero-shot variant effects tasks were also skipped, since unlike
models with an attention mechanism, each output token is determined by
a very small local context, and if one wanted to mitigate that through
pooling, the SNP token signal becomes too diluted for classification.
Evaluating those tasks with the original zero-shot protocol gives artificially low results.

For CpG methylation, the encoded sequence is pooled and passed through a linear head. For gene finding, each token is passed through a linear head.

\subsubsection{Chromatin Profile Prediction}
This task \citep{zhouPredictingEffectsNoncoding2015} consists of predicting
chromatin profiles and epigenetic markers given a DNA sequence. The
dataset consists of 919 chromatin features, grouped into transcription
factor binding profiles, DNase I hypersensitivity, and histone marks.

Even though the dataset's sequences were sourced from hg19, in this specific case, for
canonicalization, hg38 is used as the source genome in order to use the
most up-to-date annotations, and the coordinates are resolved directly
by aligning the DeepSEA sequences with minimap2
\citep{liMinimap2PairwiseAlignment2018}.

\label{sec:methods_optimal_canonicalization_search}

The canonicalization pipeline and its parameters were optimized using Optuna \citep{akibaOptunaNextgenerationHyperparameter2019} using its default TPE optimizer. 20 trials were run to optimize the following parameters:

\begin{itemize}
	\item \texttt{annotations\_level}: Filter the GENCODE annotations to use up to level 1 (validated), 2 (manually annotated), or 3(automatically annotated).
	\item \texttt{transformation}: Whether to canonicalize a sequence by taking the RC, the complement, or the reverse of it.
	\item \texttt{overlap\_transformation\_behavior}: When encountering a segment \textbf{A} that overlaps with another segment \textbf{B} in the opposite orientation, this variable controls the expected behavior of transforming \textbf{A}:
	\begin{enumerate}
		\item If \texttt{overlap\_transformation\_behavior} is set to \texttt{partial break}, then it's believed that only the overlapping part between \textbf{A} and \textbf{B} breaks
		\item If \texttt{overlap\_transformation\_behavior} is set to \texttt{full break}, then it's believed that the \emph{whole} \textbf{B} segment breaks. It's behaviour depends on other variables specific to this.
		\item If \texttt{overlap\_transformation\_behavior} is set to \texttt{both break}, then it's believed that both \textbf{A} \emph{and} \textbf{B} break. The algorithm chooses to either leave the sequence as-is(and leave \textbf{B} badly oriented) or to take the RC of the whole sequence(and leave \textbf{A} badly oriented) depending on which one is the longest segment
	\end{enumerate}
	
	See section \ref{sec:design-of-the-canonicalization-algorithm} for more details on the variables used and a more detailed explanation on the different canonicalization algorithms and the way they deal with overlapping segments.
	
	\item \texttt{include\_cdjv\_segments}: Whether to count the
	constant and V(D)J segments of the human and mouse adaptive immune system as features that should induce canonicalization or not.
	\item \texttt{include\_pseudogenes}: Whether to count pseudogenes or not as features that should induce canonicalization.
\end{itemize}

See section \ref{sec:hyperparameter-optimization-results} for the values chosen for these parameters and more details on the HPO results.

20 trials were used, even though the number of possible configurations (180) is much larger than the 20 trials used, most of the parameters had very little importance, and the improvements were starting to become marginal. See section \ref{sec:hyperparameter-optimization-results} for more details on the results. It should also be noted that some of the variables are conditioned by others (see section \ref{sec:design-of-the-canonicalization-algorithm}).

To speed up the trials, the model was pretrained and fine-tuned with a
single configuration and the same pretraining weights for every downstream task, in order to obtain representative metrics for the configuration without having to use a different pretraining run per benchmark. See section \ref{hyperparameter-search} for more details on the model configuration.

Each trial was evaluated on all downstream tasks, and its score was computed by averaging the z-score across those tasks. The mean and variance for those z-scores were obtained from the 5 baseline runs mentioned previously on section \ref{sec:methods_evaluation_canonicalizaiton_algorithms}. 

Even though there is a considerable task-type imbalance (there are many more histone-marks-related tasks than splicing-related tasks, for example), because there is little to no correlation between tasks, the score for each trial was obtained by simply averaging the z-scores for all tasks.

\section{Discussion}

Even though the leakage control model has a higher score than the baseline and canonicalized model on almost all tasks, it can't be discerned whether it comes from the possible data leakage mentioned on section \ref{sec:methods_evaluation_canonicalizaiton_algorithms}, or the exploitation of asymmetries. What is certain is that even if exploiting the asymmetry is beneficial, implementing that exploitation through canonicalization doesn't work for architectures like ConvNova.

It's noted that even though there could be a small improvement on the \texttt{demo\_human\_or\_worm} task from Genomic Benchmark, it can't be known (assuming there's a true improvement) if it comes from the exploitation of transcriptional asymmetry, or through simpler reasons, like the difference in length, frequency and number of genes in human vs C. elegans genomes \citep{eichingerGenomeSocialAmoeba2005}

\subsection{Future work}.
Regarding future work, one could:
\begin{itemize}
	\item Try to find another way to incorporate the transcriptional asymmetry into a model to assess whether this information can be exploited for better performance
	\item Modify the data used by the canonicalization method to evaluate it on the exploitation of the replicational asymmetries also mentioned by \citet{moeckelStrandAsymmetriesGenomic2023}
	\item Evaluate the canonicalization method on a different architecture, like HyenaDNA\citep{nguyenHyenaDNALongRangeGenomic2023}
\end{itemize}

\subsection{Design of the canonicalization algorithm for overlapping segments}\label{sec:design-of-the-canonicalization-algorithm}
Regarding the approach to dealing with overlapping segments, 3 variables were proposed with which to formulate all the
hypotheses of the optimal algorithm: 

\begin{itemize}
	\item \emph{\texttt{overlap\_transformation\_behavior}}: Determines the different hypotheses for what happens when canonicalizing a segment \textbf{A} that overlaps with a segment \textbf{B}:
	\begin{itemize}
		\item \emph{Partial break}: Only the overlapping part between \textbf{A} and \textbf{B} of both segments breaks.
		\item \emph{Full break}: The entire segment \textbf{B} is broken when partially
		canonicalizing one of its parts.
		\item \emph{Both break}: Both \textbf{A} and \textbf{B} are entirely broken, since that overlapping part needed to be kept intact for both segments to be understood correctly by the model.
	\end{itemize}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.7\textwidth]{overlap_break_behavior.png}
	\end{figure}
	
	\item \emph{\texttt{orient\_all\_segments}}: A binary variable indicating whether it
	is necessary for all segments to be in the canonical orientation, or
	if the algorithm can ignore certain segments if the cost of ignoring
	them (the number of nucleotides) is lower than the cost of
	canonicalizing them (the number of nucleotides it destroys, which is
	calculated depending on \texttt{overlap\_transformation\_behavior}). The
	only case where it's irrelevant is when
	\texttt{overlap\_transformation\_behavior = partial\_break}. This is explained in more detail below.
	
	\item \emph{\texttt{keep\_segments\_order}}: In the case where
	\texttt{overlap\_transformation\_behavior = full\_break} or \texttt{both\_break} and
	\texttt{orient\_all\_segments=True} there are 2 ways to canonicalize the
	segments, one that breaks the fewest nucleotides but destroys the
	original order of the segments, and another where that original order is
	kept but more nucleotides are destroyed. This variable decides which of
	the 2 ways to use. They are described in detail on \ref{sec:appendix_canonicalization_keep_segments_order_true}
\end{itemize}

Based on all the possible permutations of these variables, the following
canonicalization methods arise:
\begin{enumerate}
	\item If \texttt{overlap\_transformation\_behavior=partial\_break},
	\texttt{orient\_all\_segments} (and \texttt{keep\_segments\_order}) have no effect since the cost of ignoring a segment is always \(\geq\) the cost
	of canonicalizing it, because the length of the overlap is always less
	than or equal to the length of the segment, so all segments are
	oriented, regardless of whether there is an overlap or not
	\\
	\item If \texttt{overlap\_transformation\_behavior=full\_break}, there are 3
	possible canonicalization algorithms. They all rely on building a \emph{conflict window} first. When a negative segment that overlaps with a positive one is found, the set of the whole ``chain'' of overlapping segments is computed recursively. This set is defined as the conflict window.
	
	The reason conflict windows are used instead of simply looking at
	immediate overlaps, is that there are cases where only looking at
	immediate overlaps ends up in a bad decision. As shown in Figure~\ref{fig:conflict_window_example}, for example,
	if I decide whether to canonicalize \textbf{A} or not:
	\begin{enumerate}[label=\alph*]
		\item If I only check the immediate overlaps, then I do not canonicalize \textbf{A} since it is
		preferable to destroy it rather than \textbf{B} (because \textbf{B} is longer)
		
		\item If I check the entire conflict window, it is preferable for me to canonicalize the
		negative segments (100bp) and destroy \textbf{B} rather than ignore them.
	\end{enumerate}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.5\textwidth]{conflict_window.png}
		\caption{Example showing the reason behind the usage of conflict windows}
		\label{fig:conflict_window_example}
	\end{figure}
	
	After the conflict window is built, the canonicalization algorithm branches in:
	\begin{enumerate}
		\item If \texttt{orient\_all\_segments=False}, then the cheapest option is chosen. Orient the negative segments at the cost of destroying the positive ones (the sum of the lengths of positive segments in the conflict window), or ignore the negative segments, at a cost equal to the sum of their lengths.
		
		\item If \texttt{orient\_all\_segments=True}, then there are 2 ways to deal with the overlapping segments:
		
		\begin{enumerate}
		\label{sec:appendix_canonicalization_keep_segments_order_true}
			\item If one wishes to keep the exact relative order of the segments as they were (\texttt{keep\_segments\_order=True}), then, across the whole genome, one can either canonicalize the segments from the - to the + strand in all of the conflict windows, or canonicalize the segments from the + to the - strand in all of them, and then take the RC of the entire genome to bring them all to the + strand.
			
			\medskip
			Although the original absolute order of the segments is not maintained when applying the second option, relative order of ``which one follows which'' is still maintained. An example of this canonicalization method can be seen on Figure~\ref{fig:canon_ordered_segments}
			
			\begin{figure}[H]
				\centering
				\includegraphics[width=\textwidth]{ordered_segments_canonicalization.png}
				\caption{}
				\captionsetup{labelsep=none}
				\label{fig:canon_ordered_segments}
			\end{figure}
			
			=== TODO. EN "SOME ARE REVERSED" ASEGURARME QUE LA TRANSFORMACION ELEGIDA POR EL HPO NUEVO SEA REVERSE O RC===
			
			\item If the canonicalization with the lowest cost is desired, regardless of the relative order of the segments, a procedure similar to the previous one is applied but scoped at the conflict window level instead of the whole chromosome level. The reason the order is lost is that some overlap windows are reversed and others are not (if the transformation isn't set to \texttt{complement}), causing the order to be lost at the genomic level. An example of this method can be seen below on Figure~\ref{fig:keep_order_false_example}
			
			\begin{figure}[H]
				\centering
				\includegraphics[width=\textwidth]{keep_order_false_example.png}
				\caption{}
				\captionsetup{labelsep=none}
				\label{fig:keep_order_false_example}
			\end{figure}
		\end{enumerate}
	\end{enumerate}
	
	\item If \texttt{overlap\_transformation\_behavior=both\_break}, there are two possible canonicalization algorithms. Both algorithms consist of canonicalizing the segments that don't overlap with any segments on the opposite strand, and for the ones that do, instead of canonicalizing them --- which would always cost more, because the cost of canonicalizing them (length(\textbf{A}) + length(\textbf{B})) is always higher than the cost of ignoring them (length(\textbf{A})) --- it's chosen whether to keep the positive strand of the segments or the negative one, depending on which strand has the most coding nucleotides.
	\begin{enumerate}
		\item If \texttt{keep\_segments\_order=True} the algorithm chooses whether to canonicalize all the non-overlapping negative segments in the chromosome, or to canonicalize all the non-overlapping positive segments and then take the RC of the whole chromosome
		\item If \texttt{keep\_segments\_order=False}, the algorithm canonicalizes all the non-overlapping negative segments in the chromosome, and then, for each conflict window, it decides whether to leave it as-is or to canonicalize it.
	\end{enumerate}
	
	This algorithm is similar to the one used when \texttt{overlap\_transformation\_behavior=full\_break} and \texttt{orient\_all\_segments=False}, the only difference is in that case, all the segments(including the ones that have overlaps) are canonicalized.
\end{enumerate}

The advantages and disadvantages of the possible configurations of
\texttt{keep\_segments\_order} can be seen on Figure~\ref{fig:full_break_examples}.
\begin{itemize}
	\item In the case where \texttt{keep\_segments\_order=True}, the canonicalization is done that way because destroying the \emph{B}, \emph{D} and \emph{F} segments (110bp) is cheaper than destroying the \emph{A}, \emph{C} and \emph{E} segments (210bp)
	\item In the case where \texttt{keep\_segments\_order=False} each overlap window is processed individually, and even though the result destroys the least amount of nucleotides, the relative order between coding sequences is lost (as seen in the second conflict window)
\end{itemize}
