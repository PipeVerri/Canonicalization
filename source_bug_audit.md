# ConvNova active-path bug audit

Audit date: 2026-10-29

## Scope and method

This review follows `convnova/train.py`, the experiment configurations under `convnova/configs/experiment/`, and `convnova/hpo/phase1.py` through their selected `src.*` imports. For phase 1 it also follows the preprocessing, pretraining, downstream evaluation, and scoring paths that would execute after earlier blockers are fixed. It does not attempt to review unrelated or duplicate dead code. `Paper/paper.tex` was read for the intended methods and evaluation protocol.

The owner confirmed during this review that the HPO score should be a **plain mean**, not the current grouped mean; that the `both_break` search should include `keep_segments_order=false`; and that BEND and DeepSEA final scores and HPO scoring should use the **test split**, including after the test-tuning tradeoff was explained. The intended HG38 window-sampling policy is uncertain; the observed behavior is reported without assuming a desired replacement.

Checkboxes are open findings, not claims that past runs or paper results necessarily used this exact checkout. Severity concerns the stated trigger. Source links are relative to this repository. Unless noted otherwise, findings are based on current source, not the older `config_audit_report.md`, which was left untouched.

## Blockers and incorrect execution

- [X] **HPO-01 — Phase 1 fails on its first trial.** `build_overrides_dict` calls Optuna's nonexistent `suggest_categorial` instead of `suggest_categorical`, raising `AttributeError` before preprocessing. The exception is not caught by the study wrapper. This was also reproduced by an isolated synthetic call. Evidence: [phase1.py:38–48](convnova/hpo/phase1.py#L38-L48), [optimize_study.py:55–60](convnova/src/hpo/optimize_study.py#L55-L60).

- [x] **HPO-02 — Restarting after an early failed trial can fail before optimization.** If the last trial failed before a result created `outputs.json`, the restart logic unconditionally opens that nonexistent file. This includes a fresh study stopped by HPO-01. Evidence: [optimize_study.py:22–32](convnova/src/hpo/optimize_study.py#L22-L32), [hpo_runner.py:60–77](convnova/src/utils/hpo_runner.py#L60-L77).

- [x] **HPO-03 — One sampled override is placed under the wrong Hydra key.** In the `full_break` / `orient_all_segments=true` branch, phase 1 emits `canonicalization.full_break_config.keep_segments_order`; the declared and consumed setting is `canonicalization.keep_segments_order`. An ordinary override of the nonexistent nested key should be rejected by Hydra; even accepting that new nested key would not change the setting the canonicalizer reads. This is reachable after HPO-01 is fixed. Evidence: [phase1.py:15–23](convnova/hpo/phase1.py#L15-L23), [default.yaml:23–26](convnova/configs/canonicalization/default.yaml#L23-L26), [canonicalize_genomes.py:42–50](convnova/scripts/canonicalize_genomes.py#L42-L50), [optuna_trial.py:98–113](convnova/src/hpo/optuna_trial.py#L98-L113).

- [x] **TRAIN-01 — NT MCC targets have the wrong shape for the stateful metric.** Each NT label is returned as `[1]`, so a batch has target shape `[B, 1]`; its pooled decoder yields `[B, C]`. The task returns these unchanged and calls multiclass `MatthewsCorrCoef.update(x, y)`, which expects class targets `[B]` for `[B, C]` predictions. Loss flattening does not fix the metric input. All current NT tasks use MCC, so a metric update is expected to fail; confirm with the installed TorchMetrics version. Gene finding is different: its LM task flattens both predictions and labels. Evidence: [NT dataset:139–154](convnova/src/dataloaders/datasets/nucleotide_transformer_dataset.py#L139-L154), [tasks.py:249–266](convnova/src/tasks/tasks.py#L249-L266), [tasks.py:75–81](convnova/src/tasks/tasks.py#L75-L81), [train.py:373–380](convnova/train.py#L373-L380), [decoder attribute injection](convnova/src/tasks/decoders.py#L298-L325).

- [x] **TRAIN-02 — The NT sweep requests two nonexistent metadata keys.** The benchmark registry requests `splice_sites_donors` and `splice_sites_acceptors`, but the dataset YAML defines singular `splice_sites_donor` and `splice_sites_acceptor` and interpolates metadata using the requested `dataset_name`. Canonicalization has a plural-to-singular mapping, but training does not. These sweep tasks cannot resolve their settings. Evidence: [benchmarks.py:22–24](convnova/src/hpo/benchmarks.py#L22-L24), [nucleotide_transformer.yaml:2–5,106–116](convnova/configs/dataset/nucleotide_transformer.yaml#L2-L5), [canonicalizer alias:222–231](convnova/src/utils/canonicalization/downstream_tasks.py#L222-L231).

- [x] **TRAIN-03 — All default DeepSEA variants use an invalid zero-worker DataLoader configuration.** DeepSEA sets `num_workers: 0`, but the inherited loader passes `prefetch_factor=4` unconditionally. PyTorch rejects a non-`None` prefetch factor with zero workers. The same issue applies to other families if their dataset worker count is overridden to zero. Evidence: [chromatin_profile.yaml:13](convnova/configs/dataset/chromatin_profile.yaml#L13), [genomics.py:243–256](convnova/src/dataloaders/genomics.py#L243-L256).

- [x] **TRAIN-04 — BEND baseline requires an unrelated parsed-control directory.** The BEND constructor always converts `control_signals_dir` to a path and asserts it exists, even when `use_control_signal: false`. Thus a baseline HDF5 file alone cannot run. In this checkout the default parsed-control directory is absent. Evidence: [BEND dataset config:27–28](convnova/configs/dataset/bend_benchmark.yaml#L27-L28), [genomics.py:302–310](convnova/src/dataloaders/genomics.py#L302-L310).

- [x] **CONFIG-01 — BEND contains unresolved `dataset_dir` interpolations.** The active BEND config has no `dataset_dir`, but the nested variant-effect metadata references `${..dataset_dir}`. Normal configuration processing traverses nested values and later prints a resolved config, so these unused metadata paths can cause resolution to fail even for CpG/gene finding; canonicalization also imports this dataset config. Exact first failure needs an OmegaConf/Hydra reproduction in the project environment. Evidence: [bend_benchmark.yaml:1–6,63–76](convnova/configs/dataset/bend_benchmark.yaml#L1-L6), [train utilities:67–69,119–122](convnova/src/utils/train.py#L67-L69), [config traversal:111–124](convnova/src/utils/config.py#L111-L124).

- [x] **TRAIN-05 — Direct paper and raw-control fine-tuning can inherit an incompatible pretraining checkpoint.** Downstream baselines specify a fixed small baseline checkpoint; paper NT changes model width/kernel, paper Genomic changes expansion, and raw-control variants add an input channel. Unless the user supplies the matching checkpoint, an existing baseline checkpoint will have incompatible tensor shapes. Non-strict loading does not ignore size mismatches. The intended HPO wrapper injects its own pretraining path, so this is specifically a direct-invocation/default-path problem; checkpoint contents were not inspected. Evidence: [baseline NT:49–55](convnova/configs/experiment/baseline/nt_benchmark.yaml#L49-L55), [paper NT](convnova/configs/experiment/paper/nt_benchmark.yaml), [paper Genomic](convnova/configs/experiment/paper/genomic_benchmark.yaml), [model input channels](convnova/src/models/ConvNova/convnova.py#L75-L82), [HPO checkpoint injection](convnova/src/hpo/full_eval.py#L19-L25).

## Training data, schedules, and metrics

- [x] **DATA-01 — HG38 pretraining always takes the same short prefix of each BED interval.** The local BED has 38,171 intervals, all 131,072 bases long; 34,021 are train. With the selected length 1,024 and `shift_augs=None`, the loader takes the first 1,024 bases of each interval, with no random offset. Thus only 1/128 of each interval is visited by this path, repeatedly, before accounting for masking or EOS. This applies to baseline, paper, and HPO pretraining. Whether fixed-prefix sampling was intended remains an open question. Evidence: [HG38 interval extraction:117–121](convnova/src/dataloaders/datasets/hg38_dataset.py#L117-L121), [BERT item:389–400](convnova/src/dataloaders/datasets/hg38_dataset.py#L389-L400), [dataset setup:1103–1123](convnova/src/dataloaders/genomics.py#L1103-L1123), [pretrain config:33–45](convnova/configs/experiment/baseline/pretrain.yaml#L33-L45).

- [x] **SCHED-01 — HG38 schedule is based on a fictional sample count.** The scheduler assumes `ceil(1,000,000,000/1024) = 976,563` examples, but this loader creates one example per BED row: the local training split has 34,021. At the default one-device batch 512, that is approximately 67 updates/epoch versus the configured 1,908. For the 200-epoch small run, the configured 381,600-step horizon and 3,816-step warmup exceed the actual approximately 13,400 updates and about 57 epochs of warmup, respectively, assuming full epochs and default loader behavior. This is independent of whether the prefix selection in DATA-01 is intentional. Evidence: [bert_hg38.yaml:14](convnova/configs/dataset/bert_hg38.yaml#L14), [pretrain schedule](convnova/configs/experiment/baseline/pretrain.yaml#L50-L55), [dataset length](convnova/src/dataloaders/datasets/hg38_dataset.py#L365-L384).

- [x] **SCHED-02 — BEND scheduler counts do not match the actual HDF5 train splits.** The configured `train_len` is 4,780 for CpG and 109,717 for gene finding, while `h5dump` reports 743,095 and 4,783 train sequences, respectively, in the locally configured `data/bend_benchmark/bend_benchmark.h5`. The schedule uses the YAML values as example counts. At global batch 256 and 10 epochs, it configures 190 steps for CpG versus about 29,030 actual updates, and 4,290 for gene finding versus about 190 actual updates; the latter figures depend on Lightning's handling of final partial accumulation. The local HDF5 is a snapshot, so recheck if the file changes. Evidence: [BEND metadata](convnova/configs/dataset/bend_benchmark.yaml#L20-L21), [CpG/gene counts](convnova/configs/dataset/bend_benchmark.yaml#L32-L53), [BEND scheduler](convnova/configs/experiment/baseline/bend_benchmark.yaml#L27-L32), [HDF5 runtime loading](convnova/src/utils/bend_benchmark_h5.py#L27-L31).

- [x] **DATA-02 — Multiworker pretraining could race on a shared FASTA handle.** `BertHG38Dataset` opened `pyfaidx.Fasta` before worker creation, without reopening it in the workers. Forked workers could therefore share an underlying file offset. The pretraining loader now uses the worker initialization hook, and both BERT pretraining datasets reopen their FASTA handles in each worker. Regression tests cover train, validation, and test loaders, including raw controls and the fixed-length dataset. Evidence: [BERT dataset](convnova/src/dataloaders/datasets/hg38_dataset.py), [fixed-length dataset](convnova/src/dataloaders/datasets/hg38_fixed_dataset.py), [worker hook](convnova/src/dataloaders/genomics.py#L35-L42), [regression tests](convnova/tests/test_hg38_workers.py).

- [x] **DATA-03 — Genomic Benchmark class IDs can differ by split.** Each split independently maps class directories to IDs using unsorted filesystem iteration. If train and test enumerate classes in different orders, the same class receives different labels, silently corrupting the accuracy and checkpoint selection. Canonicalized split directories can also be created separately. Local Genomic Benchmark data were unavailable, so an actual mismatch was not measured. Evidence: [genomic_bench_dataset.py:169–203](convnova/src/dataloaders/datasets/genomic_bench_dataset.py#L169-L203), [canonicalizer directory creation](convnova/src/utils/canonicalization/downstream_tasks.py#L301-L320).

- [ ] **METRIC-01 — Configured pretraining perplexity and token-count metrics are not updated.** The pretraining pipeline declares stateful `perplexity` and `num_tokens`, but `_shared_step` only updates/logs stateful names `mcc` and `auroc`. This loses the configured metrics, even if loss-based training succeeds. Evidence: [bert_hg38 pipeline:14–17](convnova/configs/pipeline/bert_hg38.yaml#L14-L17), [train.py:363–393](convnova/train.py#L363-L393).
 (skipped purposely)
- [x] **DATA-04 — RC augmentation and raw controls diverge under an override.** For Genomic Benchmark, enabling `rc_aug` transforms the sequence but leaves its positional raw control unchanged; the control should be reconciled with the transformed sequence's positions and strand convention. This is not active in the default configs. The corresponding NT RC augmentation also calls `coin_flip()`, which calls an imported `random` module as if it were a function. Evidence: [Genomic augmentation/control](convnova/src/dataloaders/datasets/genomic_bench_dataset.py#L214-L238), [NT coin flip](convnova/src/dataloaders/datasets/nucleotide_transformer_dataset.py#L1-L12), [NT augmentation](convnova/src/dataloaders/datasets/nucleotide_transformer_dataset.py#L120-L122).

## Evaluation and research-protocol inconsistencies

- [x] **EVAL-01 — HPO uses an equal mean of groups, not the requested equal mean of tasks.** Each of eight groups contributes 1/8 regardless of the number of tasks in it; for example, a singleton task receives ten times the weight of an individual member of the ten-task histone group. This contradicts the owner's confirmed intent and the plain task mean described in [paper.tex:513–515](Paper/paper.tex#L513-L515). Evidence: [optuna_trial.py:29–70,72–96](convnova/src/hpo/optuna_trial.py#L29-L96).

- [x] **EVAL-02 — DeepSEA HPO/final evaluation uses validation, not the requested test split.** Its experiment explicitly excludes the test loader, although the datamodule loads a distinct test set. The local arrays have 8,000 validation and 455,024 test examples. Baseline HPO metric metadata requests `val/auroc`, and the scorer selects the first returned evaluation dictionary. Evidence: [chromatin experiment:33–35](convnova/configs/experiment/baseline/chromatin_profile_prediction.yaml#L33-L35), [loader filtering](convnova/train.py#L670-L694), [baseline metrics](convnova/hpo/baseline_metrics.json), [scorer](convnova/src/hpo/optuna_trial.py#L15-L27).

- [x] **EVAL-03 — BEND HPO score uses validation, not the requested test split.** Unlike DeepSEA, the current BEND experiment retains both loaders. Nevertheless the scorer reads the first returned summary and `baseline_metrics.json` names `val/auroc` and `val/mcc` for CpG and gene finding. The test score may be evaluated and returned separately, but it is not the selected HPO score. Changing just the trial metric without recomputing matching baseline test means and standard deviations would make z-scores inconsistent. Evidence: [BEND experiment:34–36](convnova/configs/experiment/baseline/bend_benchmark.yaml#L34-L36), [evaluation order](convnova/train.py#L670-L694), [scorer](convnova/src/hpo/optuna_trial.py#L15-L27), [baseline metrics](convnova/hpo/baseline_metrics.json).

- [x] **EVAL-04 — NT and Genomic Benchmark test splits are used for model selection and HPO.** Both datasets map `val` to the official `test` split, and their pipelines monitor validation metrics to select the best epoch. Phase 1 further uses those results to choose hyperparameters. Consequently these are test-tuned scores, not independent held-out estimates. This is a methodological issue even if the datasets provide no separate validation split. Evidence: [NT mapping](convnova/src/dataloaders/datasets/nucleotide_transformer_dataset.py#L71-L73), [Genomic mapping](convnova/src/dataloaders/datasets/genomic_bench_dataset.py#L169-L171), [NT monitor](convnova/configs/pipeline/nucleotide_transformer.yaml#L17-L19), [Genomic monitor](convnova/configs/pipeline/genomic_benchmark.yaml#L10-L13), [HPO scorer](convnova/src/hpo/optuna_trial.py#L72-L96).

- [x] **EVAL-05 — Pretraining selects its checkpoint using test loss.** The pipeline monitors `test/loss`, and the validation loop evaluates test alongside validation every epoch. The selected `checkpoints/test/loss.ckpt` is therefore test-selected, not an independently held-out pretraining test result. Evidence: [bert_hg38 pipeline:10–12](convnova/configs/pipeline/bert_hg38.yaml#L10-L12), [train.py:670–694](convnova/train.py#L670-L694), [HPO checkpoint path](convnova/src/hpo/full_eval.py#L19-L21).

- [x] **EVAL-06 — Using BEND/DeepSEA test scores as the HPO objective tunes on those test sets.** The owner explicitly requested test-based HPO scoring; implementing EVAL-02/03 accordingly would satisfy that request, but the winning trial's score would no longer be an independent final test estimate. This is a statistical consequence, not a claim that the requested policy is accidental. Consider a separate held-out evaluation if an unbiased final estimate is needed.

- [x] **EVAL-07 — The HPO search omits the requested `both_break` / `keep_segments_order=false` mode.** Phase 1 fixes the default `keep_segments_order: true` for `both_break`, although the active implementation has materially different chromosome-wide and conflict-window branches for true and false. The owner confirmed that the latter should be included in the search. Evidence: [phase1.py:33–36](convnova/hpo/phase1.py#L33-L36), [default](convnova/configs/canonicalization/default.yaml#L23-L26), [algorithm branches](convnova/src/utils/canonicalization/canonicalization_logic.py#L90-L155).

## Canonicalization and artifact integrity

- [x] **CANON-01 — Reversals can move original sequence content across HG38 split boundaries.** Canonicalized pretraining retains the original split-labeled BED but reverses individual segments and sometimes entire chromosomes. If a reversal crosses a BED split boundary, original bases change split membership without remapping BED coordinates. The transformed intervals remain distinct coordinates, but they no longer represent the original train/validation/test partition, and baseline/canonicalized comparisons are not partition-paired. Extent depends on generated segments and transformation; it was not measured. Evidence: [genome transformations](convnova/src/utils/canonicalization/canonicalization_logic.py#L271-L286), [canonicalized FASTA override](convnova/configs/experiment/hpo/canonicalized/pretrain.yaml#L2-L8), [BED split selection](convnova/src/dataloaders/datasets/hg38_dataset.py#L365-L371).
 ( I dont care about this because pretraining is just about MLM, the genomic structure doesn't matter)
- [x] **CANON-02 — Annotation projection can label unaligned query bases.** Projection clamps to the sequence bounds but not to `q_st:q_en` or `r_st:r_en`. An isolated execution of the actual method with a plus-strand alignment `q=[20,100)`, `r=[100,180)` and annotation `[90,110)` returns query `[10,30)` instead of the aligned overlap `[20,30)`. This can inflate the >50% decision and extend control signals or partial transformations into clipped bases. The reverse strand has the analogous issue. Evidence: [parsed_genome.py:230–246](convnova/src/utils/canonicalization/parsed_genome.py#L230-L246), [consumers](convnova/src/utils/canonicalization/downstream_tasks.py#L149-L182).

- [x] **CANON-03 — Annotation projection ignores CIGAR insertions/deletions.** The same method assumes a constant offset across the alignment. Indels shift projected boundaries after the indel, affecting raw controls and partial segment transformations, and potentially the full-sequence >50% decision. The source explicitly notes this approximation; actual frequency and magnitude were not measured. Evidence: [parsed_genome.py:230–246](convnova/src/utils/canonicalization/parsed_genome.py#L230-L246).

- [x] **CANON-04 — Canonicalized FASTA drops contigs without retained annotations.** `canonicalize_genome` iterates only the annotation-derived parameter dictionary and writes only those records, rather than copying unannotated input contigs unchanged. If the BED references a missing contig, lookup fails; even without such a BED record, the output is not the complete input genome. The local BED references 23 chromosomes, but this audit did not determine whether all survive annotation filtering at every HPO level. Evidence: [annotation-derived parameter construction](convnova/scripts/canonicalize_genomes.py#L42-L55), [genome output iteration](convnova/src/utils/canonicalization/canonicalization_logic.py#L271-L288), [FASTA lookup](convnova/src/dataloaders/datasets/hg38_dataset.py#L74-L81).
( I dont care about it. hg38 and its bed are a subset of Gencode's hg38)
- [x] **CANON-05 — HPO trials share and clear generated datasets.** All trials use the same parsed-genome and downstream output directories, and downstream constructors remove existing output contents. Concurrent phase-1/preprocessing processes can delete or replace each other's data while a run is training. On a resumed failed trial, preprocessing is skipped and the current shared artifacts are assumed to be the failed trial's artifacts; another run can invalidate that assumption. Evidence: [shared paths](convnova/configs/canonicalization/default.yaml#L28-L53), [output cleanup](convnova/src/utils/canonicalization/downstream_tasks.py#L73-L87), [resume shortcut](convnova/src/hpo/optuna_trial.py#L134-L151).(Im not doing parallel trials)

- [x] **CANON-06 — HPO's reverse-only and complement-only transformations keep labels justified in the paper only for RC.** The search evaluates `reverse`, `complement`, and `rc`; sequence-level CpG/DeepSEA labels remain unchanged, while the paper's invariance argument concerns reverse complement. Reverse alone and complement alone are not the same physical-strand transformation as RC, so RC invariance does not establish label validity for those search branches. This is a scientific assumption requiring explicit justification, not proof every such label is wrong. Evidence: [phase1 transformation search](convnova/hpo/phase1.py#L40-L44), [BEND labels](convnova/src/utils/canonicalization/downstream_tasks.py#L440-L455), [DeepSEA labels](convnova/src/utils/canonicalization/downstream_tasks.py#L541-L542), [paper task classification](Paper/paper.tex#L898-L904), [CpG/DeepSEA rationale](Paper/paper.tex#L954-L967).

- [x] **CANON-07 — Main paper and appendix describe different `both_break` behavior.** The main method says both overlapping segments are left as-is, while the appendix describes optionally reversing the whole chromosome/conflict window; the active implementation also supports these broader transformations. Those claims should distinguish leaving local conflicting segments unmodified from the subsequent global/window reversal. Evidence: [paper.tex:338–340](Paper/paper.tex#L338-L340), [paper.tex:734–737](Paper/paper.tex#L734-L737), [implementation](convnova/src/utils/canonicalization/canonicalization_logic.py#L90-L155).

## HPO operational issuesI 

- [ ] **HPO-04 — Each restart requests 20 additional trials.** `load_if_exists=True` resumes the same study, but every invocation calls `study.optimize(..., n_trials=20)`. This specifies 20 trials for that invocation, not a 20-trial study-wide cap. A restart can therefore exceed the paper's stated total. Evidence: [phase1.py:64–71](convnova/hpo/phase1.py#L64-L71), [optimize_study.py:20,60](convnova/src/hpo/optimize_study.py#L20-L20), [paper.tex:484](Paper/paper.tex#L484).

- [x] **HPO-05 — Baseline and canonicalized pretraining use different source FASTA paths.** Baseline uses `hg38.ml.fa`; canonicalization reads `GRCh38.primary_assembly.genome.fa`. Differences in reference bases or masking would be confounded with canonicalization. A deterministic sample of 1,000 local training prefixes found no base differences after uppercasing, so this is an unresolved provenance/whole-genome-equivalence issue, not evidence that the local inputs differ. Evidence: [baseline input](convnova/configs/dataset/bert_hg38.yaml#L2-L3), [canonicalization input](convnova/configs/canonicalization/default.yaml#L28-L30), [canonicalized experiment](convnova/configs/experiment/hpo/canonicalized/pretrain.yaml#L7-L8).

## Environment, prerequisites, and validation limits

- The checkout currently lacks several configured HPO inputs, including `data/so.obo`, the four configured `*_index.mmi` files, the Genomic Benchmark directory, and the generated `data/parsed/canonicalized.fasta`; the NT data directory is empty. This is a local readiness observation, not necessarily a source bug. Do not run full preprocessing solely as a diagnostic: it is resource-intensive and clears generated downstream output directories.
- The current `python` lacks PyTorch, Lightning, Hydra, OmegaConf, PyYAML, pytest, and Optuna. Consequently no end-to-end composition, full test suite, training, or preprocessing was run. Hydra rejection/resolution and TorchMetrics failure descriptions are source/API-based and should be confirmed in the actual project environment.
- Read-only checks included BED row/split/interval counts, BEND HDF5 dataset dimensions with `h5dump`, DeepSEA NumPy headers, the 1,000-prefix FASTA comparison, and an isolated synthetic execution of the actual annotation-projection method. No source or generated dataset was modified.
- The current code already contains fixes for several issues described in the older audit, including full-checkpoint restoration and epoch AUROC aggregation; this report does not repeat those stale claims.

## Questions to resolve before changing behavior

1. Should HG38 pretraining sample across each 131,072-base BED interval, or is its fixed 1,024-base prefix an intentional experimental design? The owner was unsure.
2. Given the requested use of BEND/DeepSEA test scores for HPO and final reporting, is there a separate final holdout or external evaluation planned? Otherwise the reported scores should be identified as test-tuned rather than independent.
